전체 서비스 개선 및 QA 요청사항
==============================

작업 목표
--------
현재 서비스의 전체적인 분위기와 기존 기능은 유지하면서, 실제 사용자가 이용했을 때 더 재미있고 자연스럽게 느껴지도록 완성도를 높여줘. 요청한 기능을 단순히 추가하는 데 그치지 말고 기존 기능과의 호환성, 사용성, 시각적 완성도, 성능, GitHub Pages 배포 안정성까지 함께 고려해줘.

[작업 전 필수 확인사항]
1. 현재 프로젝트의 폴더 구조와 전체 코드를 먼저 분석할 것.
2. 각 기능이 어떤 파일과 컴포넌트에 구현되어 있는지 파악할 것.
3. 기존 기능 간 의존 관계와 이벤트 흐름을 확인할 것.
4. 기존에 정상 작동하는 기능과 디자인을 임의로 삭제하거나 변경하지 말 것.
5. 기존 모델, 이미지, 애니메이션, 텍스처, 컴포넌트 및 코드를 최대한 재사용할 것.
6. 새 기능을 추가하기 전에 기존 구현을 활용할 수 있는지 먼저 검토할 것.
7. 별빛 언덕을 지금 '은하재'로 이름을 바꿨으니 그렇게 알고 있어.
8. 은하재 산책은 싱글플레이 방식으로 동작하고 GitHub Pages 정적 호스팅 환경을 지원해야 함.
9. 수정 후 실제 동작을 검증하고, 테스트하지 않은 결과나 성능 수치를 정상이라고 추측해 보고하지 말 것.

1. 은하재 라이브러리 404 에러
==================================================

지금 preview로 은하재를 들어가면 아무것도 표시되지 않아
Three.js 로딩 오류가 있는 것 같아
버튼은 보이지만 버튼도 동작하지 않음
와이파이 문제인가 싶어 휴대폰 핫스팟으로 변경해도 동일한 오류가 발생해.

GET /assets/vendor/three/build/three.module.js 404 (Not Found)
Failed to load resource: the server responded with a status of 404 () https://ais-dev-...run.app/assets/vendor/three/build/three.module.js

단순히 import 경로만 변경하지 말고 프로젝트 전체 파일 구조를 확인해 줘.

404만 숨기는 임시방편은 사용하지 말고, 기존 3D 공간과 기능을 보존해 줘.

수정 후 브라우저에서 실제 모듈 요청이 200으로 응답하는지, 은하재가 렌더링되는지 확인해 줘.
-> 그리고 어떤 이유로든 은하재 공간을 정상적으로 노출하지 못하는 상황이 오면, 에러 상태로 계속 통신하도록 하지 말고 얼랏을 뛰우고 메인으로 보내버리든 해야할듯
얼랏을 띄운다면 개발적인 내용을 적기 보다는 은하재 컨셉에 맞는 문구로 띄워줘
(에러 내용이나 개발적인 내용은 console.log로 남기기)

2. 수정구슬 답변 품질 개선
==================================================

현재 수정구슬의 답변이 기대보다 재미없고 사용자의 기분을 환기하는 효과도 부족해.

예시 입력:
"일이 너무 많아. 퇴근하고 싶어."

현재 답변 예시:
"마음속으로 퇴근했다 치죠!"
"'일의 신'에게 남은 업무를 외주 주는 상상을 해봅시다."

이런 단순한 말장난이나 억지스러운 상상은 피하고, 사용자의 고민을 이해하면서도 예상하지 못한 관점으로 전환해줘.

[답변 방향]
- 사용자의 고민과 감정을 먼저 정확하게 파악할 것.
- 고민을 무조건 긍정적으로 해석하거나 억지로 위로하지 말 것.
- 뻔한 위로, 교훈, 자기계발식 조언을 지양할 것.
- 단순한 말장난이나 단어 바꾸기로 웃기려 하지 말 것.
- 의외성, 재치, 현실적인 공감, 엉뚱한 상상 등을 상황에 맞게 활용할 것.
- 사용자가 잠깐이라도 웃거나 다른 관점에서 상황을 바라볼 수 있도록 할 것.
- 매번 같은 답변 구조나 고정 템플릿을 사용하지 말 것.
- 심각하거나 민감한 고민에는 억지로 유머를 넣지 말고 진지하게 반응할 것.
- 필요하다면 실제로 해볼 수 있는 작고 구체적인 행동을 제안할 것.

[다양한 답변 접근]
상황에 따라 현실적인 공감과 예상 밖의 관점을 결합하거나, 엉뚱하지만 맥락에 맞는 상상, 새로운 해석, 사소한 행동 제안, 유머러스한 과장, 새로운 선택지 제안 등을 자연스럽게 활용해줘. 이를 고정된 순서나 템플릿으로 사용하지 말 것.

[품질 테스트 입력]
- 일이 너무 많아. 퇴근하고 싶어.
- 월요일이라 출근하기 싫어.
- 아무것도 하기 싫고 무기력해.
- 친구가 나를 서운하게 했어.
- 돈을 너무 많이 썼어.
- 요즘 재미있는 일이 없어.
- 새로운 일을 시작하고 싶은데 용기가 안 나.
- 아무 이유 없이 기분이 안 좋아.

각 입력에 대해 답변이 서로 다른 접근 방식과 분위기를 보여주는지 직접 테스트하고, 억지스럽거나 반복적인 답변을 개선해줘.

3. 은하재 개선
==================================================

현재 은하재의 분위기와 기존 기능은 유지하면서 아래 항목을 수정 및 추가해줘.

3-1. 불꽃 색상 설정 UI
- 현재 색상 이름으로 선택하는 방식을 아바타 외투 색상 선택 UI처럼 실제 색상 견본을 보여주는 방식으로 변경할 것.
- 색상 견본을 클릭하면 해당 색상이 적용되도록 할 것.
- 현재 선택된 색상이 명확하게 표시되도록 할 것.
- 기존 불꽃놀이 기능은 유지할 것.

3-2. 주요 오브젝트 위치 재배치
- 붕어빵 가게, 크리스마스 트리, 보신각이 언덕 앞쪽에 몰려 있고 겹쳐 보이므로 언덕의 앞쪽, 중앙, 뒤쪽 공간에 자연스럽게 분산 배치할 것.
- 전체 공간을 바라봤을 때 시각적으로 균형이 맞도록 할 것.
- 각 오브젝트에 접근하고 상호작용할 공간을 확보할 것.
- 기존 벤치와 강아지의 위치는 절대 변경하지 말 것.
- 플레이어의 이동 동선과 시야를 고려할 것.

3-3. 보신각 수정
- 정자 내부에 있던 벤치를 제거할 것.
- 보신각 종과 종을 치는 당목의 크기를 확대할 것.
- 실제 보신각 종의 크기와 비례를 참고해 자연스럽게 표현할 것.
- 종과 건축물이 어색하게 겹치지 않도록 위치와 크기를 조정할 것.

3-4. 붕어빵 색상
- 팥 붕어빵 색상이 너무 진하므로 조금 더 밝고 자연스러운 구운 황금빛 갈색 계열로 변경할 것.
- 지나치게 붉거나 검게 보이지 않도록 할 것.

3-5. 파란 집 기둥
- 기둥 위의 검은색 동그라미를 제거할 것.
- 불필요한 검은색 원형 장식이나 돌출 부분이 보이지 않도록 할 것.

3-6. 파란 집 창문 조명
- 창문에 따뜻한 노란빛이 켜진 것처럼 표현할 것.
- 실제 조명을 여러 개 추가하기보다 Emissive Material 등 효율적인 방식을 우선 사용할 것.

3-7. 붕어빵 가게 타이틀 제거
- 가게 위에 표시되는 '붕어빵 가게' 텍스트 타이틀을 제거할 것.
- 붕어빵 구매 기능은 기존처럼 가게 클릭으로 실행되도록 유지할 것.
- 타이틀 제거로 기존 클릭 영역이나 상호작용이 손상되지 않도록 할 것.

3-8. 멀티유저 기능 완전 제거
다음 멀티유저 기능과 관련 코드만 제거할 것.
- 다른 접속자의 아바타 표시
- 아바타 위치 및 상태 실시간 동기화
- WebSocket 연결 및 재접속 로직
- 멀티유저 관련 서버 통신
- 멀티유저 전용 상태 관리 코드
- 멀티유저 기능만을 위해 필요한 불필요한 코드

내 아바타의 이동, 외형 변경, 춤추기, 상호작용 등 싱글플레이 기능은 그대로 유지할 것. GitHub Pages에서 별도 서버 없이 실행되어야 하며, 멀티유저와 무관한 코드까지 함께 제거하지 않도록 의존 관계를 확인할 것.

3-9. 풍등 / 설경 모드

사용자가 '풍등' 또는 '설경'을 선택할 수 있도록 하고 두 모드는 동시에 실행되지 않도록 할 것.

[풍등 모드]
- 기존 하늘의 풍등 연출, 움직임, 개수 등은 유지할 것.
- 풍등 모드 전용 장식으로 나무 풍등 걸이를 추가할 것.
- 나무와 나무 사이에 작은 풍등 여러 개가 걸려 있는 형태로 구성할 것.
- 풍등은 따뜻한 주황색과 노란색 계열로 은은하게 빛나도록 할 것.
- 건축물, 나무, NPC 및 이동 동선과 겹치지 않도록 배치할 것.
- 풍등 걸이는 풍등 모드에서만 보이게 하고 설경 모드에서는 숨기거나 비활성화할 것.

[설경 모드]
- 하늘에 눈이 자연스럽게 흩날리는 효과를 추가할 것.
- 눈송이는 개별 3D 오브젝트를 무수히 생성하지 말고 THREE.Points, BufferGeometry 등을 활용해 효율적으로 구현할 것.
= 눈송이는 크기와 속도에 약간의 차이를 주어 자연스럽게 내리는 느낌을 표현할 것.
- 남산, 주변 나무, 언덕의 지붕과 벤치 등 주요 오브젝트에 눈이 쌓인 모습을 표현할 것.
- 눈이 쌓이는 표현은 기존 오브젝트의 재질이나 간단한 눈 덮임 효과를 활용할 것. 모든 오브젝트에 별도의 복잡한 눈 지형이나 메시를 추가하지 말 것.
- 눈사람을 추가하고 주변 설경과 자연스럽게 어울리도록 배치할 것.
- 크리스마스 트리와 조명은 눈 내리는 환경에 어울리도록 유지하거나 조정할 것.
- 설경 모드에서만 눈 내리기와 눈 덮임 효과가 활성화되도록 할 것.

[모드 전환 및 성능 조건]
- 풍등과 설경은 동시에 실행되지 않도록 할 것.
- 모드 전환 시 이전 모드의 오브젝트와 효과가 중복 생성되지 않도록 할 것.
- 설경 모드를 해제하거나 풍등 모드로 전환하면 눈 효과와 눈 덮임 표현을 제거하고 기존 환경을 정확히 복원할 것.
- 눈송이는 입자 수를 제한하고 기존 입자를 재사용할 것.
- 모바일에서는 기기 성능에 따라 눈 입자 수를 줄일 것.
- 사용하지 않는 효과는 화면에서 숨기는 것뿐 아니라 불필요한 업데이트와 연산도 중단할 것.
- 모드 전환 시 이전 효과의 애니메이션, 이벤트, 오브젝트가 중복되거나 누적되지 않도록 할 것.
- 기존 낮, 노을, 밤 시간대 설정 및 다른 환경 효과와 충돌하지 않도록 할 것.

3-10. NPC 4명 추가 및 기존 NPC 이름 지정

기존 아바타 및 NPC 모델을 최대한 재사용해 총 4명의 NPC를 추가할 것.

[NPC 이름 및 식별 기준]
- 모모: 강아지 옆 벤치에 앉아 있는 NPC
- 비트: 춤추는 NPC
- 토리: 대화하는 NPC 1
- 나루: 대화하는 NPC 2
- 치치: 파란집 주민
- 몽이: 강아지
- 만복: 붕어빵 가게 사장님

- 위 이름을 각 NPC의 정식 이름으로 지정할 것.
- 플레이어 아바타와 동일한 스타일로 NPC 머리 위에 이름을 표시할 것.
- 이름표의 크기, 색상, 글꼴 및 표시 위치는 기존 플레이어 이름표와 통일할 것.
- 이름표가 캐릭터나 주변 오브젝트를 과도하게 가리지 않도록 자연스럽게 배치할 것.
- NPC 이름은 개발 및 수정 시에도 각 NPC를 식별하는 기준으로 사용할 것.

A. 모모 - 강아지 옆 벤치에 앉아 있는 사람
- 강아지 옆 벤치에 자연스럽게 앉아 있도록 할 것.
- 기존 벤치와 강아지의 위치는 변경하지 말 것.
- 기존에 플레이어가 강아지 옆 벤치에 앉을 때 실행되던 강아지 짖는 소리와 강아지 움직임 기능을 완전히 제거할 것.
- NPC는 항상 벤치에 앉아 있는 상태를 유지할 것.

B. 비트 - 춤추는 사람
- 다른 오브젝트와 동선이 겹치지 않는 곳에 배치할 것.
- 반복적인 춤 애니메이션을 적용할 것.
- 몇 가지 춤 동작을 자연스럽게 번갈아 사용하고, 반복 주기마다 작은 변화를 줘 단조롭지 않게 표현할 것.
- 춤 동작이 끝나고 처음으로 돌아갈 때 움직임이 끊기거나 튀지 않도록 자연스럽게 연결할 것.
- 기존 아바타의 춤 애니메이션을 최대한 재사용할 것.
- 음악을 즐기며 자연스럽게 리듬을 타는 느낌으로 춤 애니메이션을 만들 것.
- 다음 동작을 자연스럽게 조합할 것.
(무릎을 살짝 굽혔다 펴는 바운스 동작 / 상체와 어깨를 좌우로 흔드는 그루브 / 팔을 가볍게 흔들거나 교차하는 동작 / 좌우로 발을 옮기는 간단한 스텝)
- 동작이 기계적으로 반복되지 않도록 관절별 움직임과 타이밍을 자연스럽게 조절할 것.

C. 토리와 나루 - 대화하는 사람 2명
- 두 NPC가 서로 마주 보도록 배치할 것.
- 간단한 손짓, 고개 움직임 등 대화 애니메이션을 적용할 것.
- 서로의 시선과 위치가 자연스럽게 맞도록 할 것.
- 두 NPC의 움직임이 완전히 동일하거나 동시에 반복되지 않도록 적절한 차이를 줄 것.

[NPC 기본 외형 및 리소스 조건]
- 기존 아바타 및 NPC와 동일한 그래픽 스타일과 신체 비율을 유지할 것.
- 눈과 양손이 모두 있어야 할 것.
- 마네킹처럼 보이지 않도록 자연스러운 자세와 움직임을 적용할 것.
- 모델, Geometry, Material, 애니메이션 리소스를 최대한 재사용할 것.
- 불필요한 리소스 복제나 애니메이션 계산을 추가하지 말 것.

※ NPC별 의상과 액세서리 지정은 3-16 항목을 따를 것.

3-11. NPC별 메세지 상호작용

- 동일한 문구가 연속으로 나오지 않도록 할 것.
- 대사는 로컬 배열에 미리 저장
- 클릭 이벤트가 발생할 때만 랜덤 대사 선택
- 기존 대화 UI를 재사용
- 불필요한 서버 통신이나 애니메이션 루프 추가 금지
- 이벤트 리스너와 타이머 중복 등록 방지
- 기존 NPC 애니메이션 및 상호작용 유지
- NPC별 메시지는 각각 독립적으로 랜덤 선택할 것.
- 메시지가 표시되는 동안 다른 NPC를 클릭해도 기존 메시지와 충돌하지 않도록 처리할 것.

A. 만복
정 많고 넉살 좋은 성격 · 붕어빵에 진심인 동네 인기쟁이
"오늘은 붕어빵 모양이 참 예쁘게 나왔어요!"
"어서 와요! 오늘은 팥을 아주 듬뿍 넣었답니다!"
"붕어빵은 머리부터? 꼬리부터? 그게 늘 고민이에요!"
"추운 날엔 역시 따끈한 붕어빵이 최고죠!"
"오늘은 붕어빵도 신나게 구워지는 날이에요!"
"제 붕어빵의 비밀은 넉넉한 팥 인심이랍니다!"
"붕어빵이 진짜 물고기라면 어떨까요?"
"또 만났네요! 오늘도 붕어빵 생각이 나셨나요?"

B. 모모
느긋하고 다정한 성격, 일상의 여유를 즐기기 좋아함
- "몽이랑 이렇게 나란히 앉아 있는 시간이 좋아요."
- "몽이는 지금 무슨 생각을 하고 있을까요?"
- "이런 평화로운 순간은 오래 기억하고 싶어요."
- "계절이 바뀌는 건 참 신기한 일이에요."
- "오늘 하늘은 유난히 색이 예쁘네요."
- "가끔은 이렇게 가만히 앉아 있는 것도 참 좋죠."
- "우리 몽이는 세상에서 제일 귀여워요. 그쵸?"

C. 비트
활발하고 자신감 있는 성격 · 춤과 음악을 좋아함
- "가만히 있으면 몸이 근질근질해요!"
- "오늘은 그루브가 아주 잘 타지는데요!"
- "춤에는 정답이 없어요! 마음 가는 대로!"
- "혹시 같이 춤춰볼 생각 없어요?"
- "발끝까지 신나야 진짜 춤이죠!"
- "오늘은 왠지 좋은 일이 생길 것 같아요!"
- "춤추다 보면 안 좋은 일도 싹 잊혀져요!"

D. 토리
호기심 많고 수다스러운 성격
- "오늘 마을에 새로운 소식 없었나요?"
- "아까 정말 신기한 걸 봤는데 말이에요!"
- "이곳은 구경할수록 새로운 게 보여요."
- "시간이 조금만 천천히 갔으면 좋겠어요."
- "오늘 밤에는 별이 많이 보일까요?"
- "가끔은 별일 없는 하루가 제일 좋더라고요."
- "혹시 이 근처에 재미있는 곳을 아세요?"

E. 나루
차분하고 엉뚱한 상상을 좋아하는 성격
- "저는 구름 모양 구경하는 걸 좋아해요."
- "별에도 저마다 이야기가 있을까요?"
- "오늘은 왠지 좋은 꿈을 꿀 것 같아요."
- "바람 소리를 듣고 있으면 마음이 편안해져요."
- "하루에 작은 즐거움 하나쯤은 꼭 있어야 해요."
- "시간을 멈출 수 있다면 지금을 멈추고 싶어요."
- "저 멀리 어딘가에도 이런 곳이 있을까요?"
- "오늘 하루도 나름 괜찮았죠?"

F. 몽이
주인인 모모를 좋아하고 말을 잘 듣는 성격.
몽이는 강아지이므로, 클릭 시 멍멍 짖는 효과음을 넣는다.

3-12. 불꽃놀이에 대한 NPC 반응

대상은 비트, 토리, 나루, 모모이며, 만복과 치치, 몽이는 제외할 것.

[불꽃 발사 및 폭발 반응]
- 불꽃이 발사되는 순간 대상 NPC들이 발사 방향의 하늘을 바라보도록 고개와 상체를 자연스럽게 들어줄 것.
- 불꽃이 하늘에서 터지는 순간 일부 NPC만 가볍게 점프하거나 손을 흔들도록 할 것.

캐릭터별 기본 반응은 다음과 같이 구분할 것.
- 비트: 하늘을 바라본 뒤 일정 확률로 가볍게 점프하거나 신나게 손을 흔들 것.
- 토리: 하늘을 바라본 뒤 일정 확률로 손을 흔들며 반응할 것.
- 나루: 대부분 조용히 하늘을 바라보며 감상할 것.
- 모모: 하늘을 바라보고, 낮은 확률로 가볍게 손을 흔들 것.
- 반응 확률과 동작 시작 시점은 NPC마다 다르게 설정해 자연스러운 차이를 줄 것.
- 불꽃 하나가 발사되면 발사 순간 하늘을 바라보고, 폭발 순간에는 일부 NPC만 추가 동작을 실행할 것.
- 여러 개의 불꽃이 연속으로 발사되면 NPC마다 서로 다른 타이밍으로 반응하도록 할 것.
- 짧은 시간 안에 동일한 동작이 반복되지 않도록 반응 간격과 재실행 제한 시간을 설정할 것.

[기존 애니메이션 유지 및 복귀]
- 불꽃놀이 반응은 기존 애니메이션을 일시적으로 보조하는 방식으로 구현할 것.
- 기존 춤이나 대화 애니메이션을 영구적으로 덮어쓰거나 손상시키지 말 것.
- 불꽃놀이가 끝나거나 취소되면 NPC별 기존 상태로 자연스럽게 복귀할 것.
- 춤추는 NPC는 춤 동작으로, 대화 중인 NPC는 대화 동작으로 복귀할 것.
- 시선과 상체 자세도 불꽃놀이가 시작되기 전의 상태로 복원할 것.
- 반응 도중 다른 애니메이션이나 이벤트가 시작되더라도 동작이 겹치거나 캐릭터 자세가 깨지지 않도록 할 것.

[이벤트 및 성능 관리]
- NPC별 반응 상태와 타이머를 독립적으로 관리할 것.
- 불꽃놀이 이벤트가 중복 등록되거나 동일한 반응이 여러 번 실행되지 않도록 할 것.
- 불꽃놀이가 종료되거나 취소되면 관련 타이머와 임시 상태를 정리할 것.
- NPC가 불꽃놀이 반응을 실행 중일 때 같은 반응이 중복 실행되지 않도록 할 것.
- 기존 NPC 애니메이션 시스템과 충돌하지 않도록 별도의 반응 상태 관리 방식을 활용할 것.

3-13. NPC의 플레이어 접근 반응
- 플레이어가 일정 거리 안으로 접근하면 NPC가 플레이어 쪽으로 고개를 돌려 바라보도록 할 것.
- 일부 NPC는 가볍게 손을 흔들거나 고개를 끄덕이는 인사 동작을 보여줄 것.
- NPC마다 반응 종류와 확률을 다르게 설정할 것.
- 플레이어가 멀어지면 기존 행동으로 자연스럽게 복귀할 것.
- 반복 접근 시 반응이 계속 재생되지 않도록 재반응 대기 시간을 둘 것.
- 춤과 대화 애니메이션을 유지하면서 접근 반응이 자연스럽게 섞이도록 할 것.
- 불꽃놀이 반응과 접근 반응이 동시에 발생할 경우 애니메이션 우선순위를 관리해 충돌을 방지할 것.
- 거리 기반으로 반응을 처리해 불필요한 연산을 줄일 것.

3-14. 공간 앰비언트 사운드
현재 잔잔한 기본 배경음악이 이미 있으므로 해당 음악은 유지하고 교체하거나 중복 추가하지 말 것. 배경음악과 별개로 공간을 살아 있게 느끼게 하는 작은 환경음만 추가할 것.

우선 추가할 소리:
- 붕어빵 가게 주변의 붕어빵 굽는 소리
- 필요하다면 공간 전체의 아주 은은한 바람 소리

구현 조건:
- 소리 발생 위치에서 들리는 것처럼 3D 공간 음향을 적용할 것.
- 플레이어가 멀어질수록 소리가 자연스럽게 작아지도록 할 것.
- 기존 배경음악 및 효과음 ON/OFF 설정과 충돌하지 않도록 할 것.
- 환경음 볼륨은 낮게 설정하고 소리가 겹쳐 시끄러워지지 않도록 할 것.
- 환경음을 끌 수 있도록 하되 오디오 설정을 불필요하게 복잡하게 만들지 말 것.
- 동일한 소리가 중복 재생되거나 이벤트가 누적되지 않도록 할 것.
- 모바일 및 브라우저 오디오 자동재생 정책을 고려할 것.
- 기존 배경음악과 재생 로직은 유지할 것.

3-15. 자정 카운트다운 및 새해맞이 이벤트 개선

현재 매일 23:59:50부터 메시지를 띄워 10부터 1까지 숫자를 세고, 여러 폭죽이 터진 뒤 '새로운 내일이 밝았습니다.'라는 메시지가 표시되는 방식을 개선할 것.

[하늘에 표시되는 공통 카운트다운]
- 매일 23:59:50부터 하늘에 숫자 10을 표시하고 이후 1초 간격으로 9, 8, 7 순서로 변경할 것.
- 화면에 고정된 일반 UI가 아니라 은하재의 하늘에 실제로 떠 있는 3D 오브젝트처럼 표현할 것.
- 플레이어가 하늘을 올려다봤을 때 잘 보이는 위치에 배치하고 남산타워나 다른 오브젝트에 가려지지 않도록 할 것.
- 멀리서도 읽을 수 있도록 충분한 크기와 대비를 확보할 것.
- 숫자가 바뀔 때 부드럽게 커졌다 작아지는 애니메이션과 은은한 발광 효과를 적용할 것.
- 마지막 3초에는 빛을 조금 더 강하게 해 긴장감을 높일 것.
- 나타나고 사라질 때 페이드 효과를 적용할 것.
- 플레이어의 이동이나 조작을 방해하지 않도록 할 것.
- 3D 텍스트 또는 카메라를 향하는 스프라이트 중 기존 구조와 성능에 적합한 방식을 선택할 것.
- 매초 새 오브젝트를 만들지 말고 하나의 텍스트 또는 스프라이트를 재사용해 숫자만 변경할 것.

[일반 날짜 자정 이벤트: 1월 1일~12월 30일]
- 매일 23:59:50부터 10초 카운트다운을 진행할 것.
- 깔끔하고 은은한 흰색 또는 따뜻한 황금색 숫자를 사용할 것.
- 00:00:00이 되면 기존 불꽃놀이 시스템을 활용해 짧고 간결한 축하 불꽃을 실행할 것.
- 일부 NPC가 하늘을 바라보거나 가볍게 점프 또는 손을 흔들며 반응하도록 할 것.
- 하늘에 '새로운 하루가 시작됐어.' 또는 '오늘은 어떤 하루가 될까?'와 같은 짧은 메시지를 표시할 것.
- 메시지는 잠시 보여준 뒤 자연스럽게 사라지도록 할 것.

전체 연출은 일상 속 작은 축하처럼 간결하고 은은하게 유지할 것.

[12월 31일 새해맞이 특별 이벤트]
- 12월 31일 23:59:50부터 1월 1일 00:00:00까지는 일반 날짜와 구분되는 특별한 새해맞이 연출을 실행할 것.

카운트다운:
- 일반 날짜보다 크고 화려하게 연출할 것.
- 황금빛과 은은하게 반짝이는 파티클 효과를 추가할 것.
- 마지막 3초에는 빛과 숫자 애니메이션을 강화해 기대감을 높일 것.
- 기존 배경음악은 유지할 것.
- 축하 효과음을 추가하는 경우 기존 사운드와 과도하게 겹치지 않도록 할 것.
- 자정 순간:
마지막 숫자 1이 사라지는 순간 기존 불꽃놀이 시스템을 활용해 특별 불꽃놀이를 시작할 것.
일반 날짜보다 다양한 색상과 높이, 위치를 활용해 풍성하게 연출할 것.
황금색, 은색, 붉은색 등 새해 분위기의 색상을 활용할 것.
남산타워와 언덕 주변 조명이 축제 분위기에 맞게 은은하게 빛나도록 할 것.
비트, 토리, 나루, 모모가 하늘을 바라보고 각자의 특성에 맞게 점프하거나 손을 흔들며 축하하도록 할 것.

- 비트: 목걸이 (실버 또는 골드 계열)
- 토리: 얇은 가로 스트라이프 패턴의 외투
- 나루: 크로스백 (브라운 또는 카키 계열)
- 치치: 챙이 넓은 버킷햇 (파스텔 블루 또는 라벤더 계열, 얼굴과 눈을 가리지 않는 자연스러운 디자인)
- 만복: 붕어빵 가게 주인에게 어울리는 앞치마 (크림색 또는 밝은 베이지 계열, 봉투색이랑 색상이 겹치지 않도록 할 것), 기존에 들고 있던 봉투 (그대로 유지)
- 몽이: 기존대로 유지

- 소품이 캐릭터의 신체를 뚫고 나오거나 기존 애니메이션 및 움직임에 간섭하지 않도록 할 것.
- 기존 모델과 Geometry, Material 등을 최대한 재사용해 불필요한 리소스 추가를 최소화할 것.
- 지정된 항목 외에는 임의로 의상이나 소품을 추가하거나 기존 외형을 변경하지 말 것.
- 작업 후 낮, 노을, 밤 모드에서 의상과 소품의 색상이 자연스럽게 보이는지 확인할 것.

[작업 목표]

기존 NPC의 외형과 개성은 유지하면서 각 캐릭터에 하나의 특징적인 소품을 추가해 쉽게 구분할 수 있도록 할 것.

3-17. 황금 티켓 숨겨진 보물 추가

은하재 공간 어딘가에 황금 티켓 하나를 숨겨두고, 플레이어가 이를 발견하면 특별한 메시지와 금빛 파티클 효과를 경험할 수 있도록 구현할 것.

[황금 티켓 디자인]
- 찰리와 초콜릿 공장의 황금 티켓에서 영감을 받은 디자인으로 제작할 것.
- 금빛이 도는 티켓 형태로, 기존 그래픽 스타일과 자연스럽게 어울리도록 할 것.
- 티켓 표면에 은은한 금빛 광택과 작은 반짝임 효과를 적용할 것.
- 지나치게 밝거나 화려하지 않도록 조절할 것.
- 멀리서 쉽게 발견되지 않지만 가까이에서 자세히 살펴보면 발견할 수 있도록 할 것.

[배치 및 위치 변경]
- 은하재 공간 전체에서 황금 티켓은 항상 하나만 존재하도록 할 것.
- 나무나 건물, 기존 오브젝트 주변 등 플레이어가 공간을 탐색해야 발견할 수 있는 위치에 숨길 것.
- 플레이어의 일반적인 이동 동선에서 쉽게 노출되지 않는 위치를 선정할 것.
- 티켓이 지형이나 오브젝트에 가려져 클릭할 수 없는 문제가 발생하지 않도록 할 것.
- 플레이어가 메인 화면으로 돌아갔다가 다시 은하재에 입장할 때마다 티켓의 위치가 변경되도록 할 것.
- 사전에 지정한 여러 유효한 후보 지점 중 하나를 무작위로 선택할 것.
- 기존 오브젝트와 지형, NPC의 위치 및 동선은 변경하지 말 것.

[발견 및 상호작용]
- 플레이어가 티켓에 가까이 다가가 클릭하면 발견 처리할 것.
- 티켓과 충분히 가까운 거리에서만 상호작용할 수 있도록 할 것.
- 티켓을 발견하면 티켓이 사라지고 아래의 특별한 메시지를 표시할 것.
- 발견 후에는 현재 은하재 이용 중 티켓이 다시 나타나거나 중복 발견되지 않도록 할 것.
- 메인 화면으로 돌아갔다가 재입장하면 새로운 위치에 티켓이 다시 나타나도록 할 것.
- 별도의 인벤토리, 수집 목록, 점수 또는 복잡한 보상 시스템은 추가하지 말 것.

크기가 지나치게 크거나 밝은 입자는 사용하지 말고, 은은하고 따뜻한 금빛으로 표현할 것.

티켓 오브젝트는 한 번에 하나만 생성하고 관리할 것.
기존 Geometry, Material 및 리소스를 최대한 재사용할 것.
반짝임과 금빛 파티클 효과는 가벼운 방식으로 구현하고 과도한 파티클이나 지속적인 애니메이션 계산을 추가하지 말 것.
파티클은 재사용 가능한 방식으로 관리하고, 효과가 종료되면 비활성화할 것.
메인 화면으로 이동하거나 은하재를 나갈 때 티켓 관련 리소스와 이벤트가 중복되거나 누적되지 않도록 관리할 것.
기존 플레이어 이동, 카메라, NPC 상호작용 및 다른 기능에 영향을 주지 않도록 할 것.

5. 은하재 성능 최적화 및 리소스 관리
==================================================

모든 기능을 무조건 동시에 고품질로 실행하지 말고, PC와 모바일 환경에서 안정적으로 동작하도록 설계해줘.
특히 눈, 풍등, 불꽃놀이, 조명, NPC 애니메이션이 겹칠 때 부하가 커지지 않도록 해줘.

5-1. 공통 최적화 원칙
- 기존 Geometry, Material, Texture, 모델, 애니메이션 리소스를 최대한 공유할 것.
- 동일한 오브젝트나 효과를 불필요하게 반복 생성하지 말 것.
- 파티클과 반복 효과는 가능한 한 재사용하거나 풀링할 것.
- 이벤트 리스너, 타이머, 애니메이션 루프가 중복 등록되지 않도록 할 것.
- 모드 전환이나 페이지 종료 시 사용하지 않는 리소스와 참조를 정리할 것.
- 숨겨진 효과는 렌더링뿐 아니라 불필요한 업데이트도 중단할 것.
- 매 프레임 전체 NPC나 모든 오브젝트를 무조건 검사하지 말고 필요한 경우 거리 기반 또는 낮은 빈도로 갱신할 것.
- 실제로 필요한 경우에만 그림자와 실시간 조명을 사용할 것.
- 모바일에서는 입자 수, 그림자, 효과 품질 등을 낮추는 적응형 설정을 적용할 것.
- 프레임 저하가 감지되면 효과 품질을 단계적으로 낮출 수 있도록 검토할 것.

5-2. 눈 파티클
- THREE.Points와 BufferGeometry 기반으로 구현할 것.
- 입자 수에 상한을 둘 것.
- 기존 파티클을 재사용하고 모드 전환 시 중복 생성하지 말 것.
- 모바일에서는 입자 수를 낮출 것.

5-3. 조명
- 풍등과 파란 집 창문은 Emissive Material을 우선 활용할 것.
- 풍등마다 실제 PointLight를 무분별하게 추가하지 말 것.
- 실제 조명은 꼭 필요한 곳에만 제한적으로 사용할 것.
- 불꽃놀이의 빛 효과도 과도한 실시간 조명 대신 효율적인 발광/후처리 방식을 우선 검토할 것.

5-4. NPC
- 기존 모델, Geometry, Material, 애니메이션을 재사용할 것.
- NPC 추가로 동일한 리소스가 불필요하게 복제되지 않도록 할 것.
- 플레이어와 멀리 떨어진 NPC는 업데이트 빈도를 낮추거나 필요한 애니메이션만 실행할 것.
- 접근 반응, 불꽃놀이 반응, 기본 행동의 상태 및 우선순위를 명확하게 관리할 것.

5-5. 불꽃놀이와 자정 이벤트
- 파티클을 재사용하고 최대 동시 발사 수와 입자 수를 제한할 것.
- 자정 이벤트에서 모든 효과가 한꺼번에 과도하게 실행되지 않도록 단계적으로 연출할 것.
- 모바일에서는 불꽃 입자 수와 효과 품질을 낮출 것.
- 이벤트 종료 후 타이머, 파티클, 애니메이션, 오디오가 정상적으로 정리되도록 할 것.

5-6. 오디오
- 기존 배경음악을 유지할 것.
- 동일 오디오가 중복 재생되지 않도록 할 것.
- 사용하지 않는 오디오 리소스와 이벤트를 적절히 정리할 것.

5-7. 동시 효과 실행 및 성능 관리

- 여러 시각 효과가 동시에 실행될 경우 전체 성능을 고려해 효과별 실행 우선순위를 관리할 것.
- 기본 환경과 사용자 조작에 필요한 기능을 최우선으로 유지할 것.
- 불꽃놀이와 자정 이벤트처럼 중요한 이벤트가 실행될 때는 효과의 품질을 유지하되, 불필요한 장식 효과의 입자 수와 업데이트 빈도를 일시적으로 낮출 것.
- 설경, 풍등, 불꽃놀이 등 서로 다른 파티클 효과가 동시에 중복 실행되지 않도록 관리할 것.
- 성능이 저하되면 파티클 수, 그림자, 발광 효과, 애니메이션 업데이트 빈도 순으로 단계적으로 조정할 것.
- 성능 조정으로 NPC 상호작용, 플레이어 이동, 핵심 이벤트가 중단되지 않도록 할 것.
- 효과가 종료되면 일시적으로 낮췄던 품질 설정을 기존 상태로 복원할 것.

5-8. 성능 측정 및 검증

- 주요 기능 구현 전후의 프레임 속도와 메모리 사용량을 비교할 것.
- 설경, 풍등, 불꽃놀이, NPC 애니메이션, 자정 이벤트를 각각 실행했을 때와 여러 기능을 동시에 실행했을 때를 구분해 테스트할 것.
- PC와 모바일 환경에서 각각 테스트할 것.
- 장시간 실행 후 메모리 사용량이 계속 증가하는지 확인해 메모리 누수 여부를 점검할 것.
- 실제 측정이 가능한 환경에서만 FPS와 메모리 사용량을 보고할 것.
- 측정할 수 없는 항목은 측정 불가 또는 확인하지 못함으로 명시하고 임의의 수치를 작성하지 말 것.

7. 전체 서비스 QA 및 성능 점검
==================================================

QA 테스터 관점에서 전체 서비스를 점검해줘.

7-1. 기능 테스트
- 메인 페이지 버튼 순서와 이동 경로
- 모바일 2열 버튼 레이아웃
- 시간 문답 정상 작동 여부
- 신년 타로 운세 정상 작동 여부
- 수정구슬 답변 생성 및 품질
- 찰나 사진관 정상 작동 여부
- 은하재 진입 및 이동
- 낮 / 노을 / 밤 시간대 변경
- 풍등 / 설경 모드 전환
- 풍등 걸이 표시 및 숨김
- 눈사람 및 눈 쌓인 환경 표시와 복원
- 불꽃 색상 변경
- 아바타 외투 및 소품 색상 변경
- 붕어빵 가게 클릭 및 먹기 기능
- 아바타 춤추기
- NPC 기본 애니메이션
- NPC 플레이어 접근 반응
- NPC 불꽃놀이 반응
- 자정 카운트다운 및 일반 날짜 불꽃놀이
- 12월 31일 새해맞이 이벤트
- 배경음악 및 효과음 ON/OFF
- 환경음 재생 및 음소거
- 기존 기능이 이번 수정으로 손상되지 않았는지 확인

7-2. PC 및 모바일 성능 테스트
PC와 모바일에서 각각 확인할 것.
- FPS 및 프레임 안정성
- 초기 로딩 시간
- 메모리 사용량
- CPU 및 GPU 사용량(측정 가능한 환경에서만)
- 3D 모델과 텍스처 로딩 부담
- 눈 내리기 및 불꽃놀이 실행 시 성능 저하
- NPC 애니메이션 실행 시 성능 저하
- 풍등 및 환경음 동작 시 성능
- 장시간 이용 시 메모리 누수 여부
- 화면 크기 변경 및 모바일 회전 시 레이아웃 문제
- 풍등/눈 내리기, 낮/노을/밤, NPC, 불꽃놀이가 겹치는 주요 조합에서 안정성

실제 측정하지 않은 FPS, 메모리, CPU/GPU 수치를 정상이라고 추측해 보고하지 말 것.
실제 기기 테스트를 할 수 없다면 코드 검토 결과와 실제 기기에서 측정하지 못한 항목을 구분해 명시할 것.

7-3. GitHub Pages 배포 호환성
- 모든 에셋 경로가 정적 호스팅 환경에서 정상적으로 해석되는지 확인할 것.
- 절대 경로 때문에 404가 발생하지 않는지 확인할 것.
- 상대 경로와 파일명 대소문자 오류를 확인할 것.
- Three.js 및 외부 라이브러리 로딩을 확인할 것.
- 이미지, 오디오, 3D 모델 로딩을 확인할 것.
- WebSocket, Node.js 서버 또는 별도 백엔드에 의존하는 코드가 남아 있지 않은지 확인할 것.
- 새로고침 및 직접 URL 접근 시 정상 작동하는지 확인할 것.
- GitHub Pages의 프로젝트 경로 하위 배포 환경에서도 정상 작동하는지 확인할 것.
