2. 파란 집 클릭하면 뜨는 '반가워요' 문구 이거 없애줘 어차피 치치 클릭하면 메세지 나오니까...
3. 치치 집을 좀 더 멋있는 것으로 바꿔줄 수 있어? 마당있는 집으로...
4. 플레이어 닉네임 없을 때 기본 값을 '행복한 밤송이' 로 해줘
5. NPC/플레이어 외형 변경
- 만복씨 짙은 그린 외투로 변경하고 캡 모자를 씌워줘
- 토리는 브라운 외투를 입고, 분홍색의 털모자(플레이어가 쓰는 모자)를 씌워줘
- 나루는 주황 외투를 입고, 짙은 그레이색의 챙모자(버킷햇이랑 다르고 챙이 너무 넓진 않게)를 씌워줘(치치가 모자 눌러쓴만큼 눌러쓰기), 외투에 버튼 빼줘
- 치치의 모자는 진한 남색으로 변경하고, 외투에 버튼을 넣어줘
- 플레이어는 금색의 귀걸이를 추가해줘

6. 치치 집 클릭해서 보면, 치치 집이랑 치치가 왜케 밝아보이지? 조명이 쎈 것같아 좀 줄여줘
7. 신규 기능 추가 (별똥별 및 우체통)
기존 은하재의 디자인, 분위기, 3D 환경과 기능을 유지하면서 아래 두 가지 기능을 추가할 것. 
기존 프로젝트의 구조와 구현 방식을 먼저 확인하고, 기존 코드와 자연스럽게 통합할 것. 기존 기능을 삭제하거나 임의로 변경하지 말 것.

7-1. 별똥별 연출
은하재의 밤하늘에 가끔 별똥별이 지나가는 연출을 추가할 것.
밤 모드에서만 등장하도록 할 것.
일정한 간격으로 반복되지 않도록 불규칙한 시간 간격으로 등장시킬 것.
밤하늘 한쪽에서 반대쪽으로 짧고 자연스럽게 지나가도록 구현할 것.
별똥별은 은은하게 빛나는 꼬리를 가진 형태로 표현할 것.
지나간 후에는 흔적 없이 자연스럽게 사라지도록 할 것.
별똥별이 지나가는 동안 별도의 버튼이나 안내 문구를 표시하지 말 것.
별똥별의 등장 빈도와 지속 시간은 은하재의 고요한 분위기를 해치지 않도록 설정할 것.
기존 하늘, 달, 조명 및 불꽃놀이 연출과 충돌하지 않도록 할 것.

7-2. 우체통
은하재에 작은 우체통 오브젝트를 추가하고, 플레이어가 우체통을 클릭하면 편지를 읽거나 직접 편지를 보낼 수 있도록 구현할 것.

7-2-1. 우체통 디자인 및 배치
은하재의 전체 분위기와 어울리는 작고 아기자기한 디자인으로 제작할 것.
맨 왼쪽 가로등 언저리에 두면 어떨까?
주변 환경과 자연스럽게 어울리도록 배치할 것.
우체통이라는 것을 쉽게 알아볼 수 있도록 디자인할 것.
플레이어가 클릭하면 편지 기능을 이용할 수 있도록 할 것.
기존 오브젝트의 위치와 동선, 다른 상호작용 기능을 방해하지 않도록 할 것.

7-2-2. 편지 읽기
우체통을 열면 은하재 어딘가에서 방문자에게 편지를 보내온 듯한 경험을 제공할 것.
편지 발신자 설정
- 편지 발신자는 기존 은하재 NPC가 아닌, 은하재 어딘가에 살거나 이곳과 인연이 있는 정체불명의 사람들로 설정할 것.
- 특정 NPC의 이름이나 캐릭터를 발신자로 사용하지 말 것.
- 발신자는 '어느 다정한 사람', '먼 곳에 사는 친구', '이름 모를 누군가' 등 다양하게 표현할 것.
- 발신자의 정체나 구체적인 배경을 지나치게 설명하지 말 것.
- 편지마다 발신자의 분위기와 말투에 약간의 개성을 부여할 것.
- 최대 3통의 편지 확인 가능. 그 이상 읽으려고 할 시 더 읽을 수 없다는 메세지는 띄울 것. (다시 메인 타고 은하재에 오면 읽을 수 있음)

편지 콘텐츠
- 편지의 구체적인 내용은 AI가 직접 창작할 것.
- 초기 편지는 최소 20종 이상 작성할 것.
- 동물의 숲에서 NPC들이 보내주는 편지나 방명록처럼 다정하고 포근하며 아기자기한 분위기를 참고할 것.
- 일상의 소소한 이야기, 계절과 날씨, 안부, 작은 응원, 귀여운 에피소드 등을 소재로 활용할 것. 
- 지나치게 감성적이거나 교훈적인 문장, 인위적인 위로는 피할 것.
- 실제 누군가가 쓴 편지처럼 자연스럽게 작성할 것.
- 편지는 한 번 읽기에 부담 없는 짧은 분량으로 작성할 것.
- 편지마다 시작 문장, 소재, 내용, 마무리 표현이 겹치지 않도록 다양하게 구성할 것.
- 편지마다 발신자 이름 또는 서명을 포함할 것.
- 우체통을 열 때마다 준비된 편지 중 하나를 무작위로 보여주되, 같은 편지가 연속으로 등장하지 않도록 할 것.
- 편지 콘텐츠는 코드 내부의 배열로 관리하여 추후 쉽게 수정하거나 추가할 수 있도록 할 것.

7-2-3. 편지 보내기
방문자가 직접 편지를 작성해 서비스 운영자인 나에게 보낼 수 있도록 구현할 것.
편지 읽기와 편지 보내기를 구분하여 선택할 수 있도록 할 것.
편지 보내기 화면에서 작성자 이름과 편지 내용을 입력할 수 있도록 할 것.
편지 내용은 적절한 글자 수 제한을 둘 것.
보내기 전에 작성한 내용을 확인할 수 있도록 할 것.
보내기 버튼을 누르면 실제로 운영자인 나의 이메일 주소로 편지가 발송되도록 할 것. (pg.miji@gmail.com)
방문자가 보낸 편지는 다른 방문자에게 공개하지 않을 것.
이메일 발송이 완료된 경우에만 전송 완료 메시지를 표시할 것. (발송에 실패한 경우에도)
중복 발송을 방지할 것.
이메일 주소와 발송 관련 비밀키 등 민감한 정보가 클라이언트 코드에 노출되지 않도록 할 것.

7-2-4. 이메일 발송 구현 조건
현재 프로젝트는 GitHub Pages 기반의 정적 웹사이트이므로 브라우저에서 이메일을 직접 발송하는 방식으로 구현하지 말 것.
외부 이메일 발송 서비스 또는 서버리스 함수를 활용할 것.
데이터베이스를 새로 구축하지 않고도 이메일 발송이 가능하도록 구성할 것.
이메일 발송에 필요한 외부 서비스와 설정 항목을 먼저 확인하고, 실제 연동에 필요한 작업을 명확하게 구분할 것.
이메일 발송 기능을 구현하지 못한 상태에서 발송이 완료된 것처럼 표시하지 말 것.
스팸 및 악의적인 반복 발송을 방지하기 위한 입력 검증과 발송 횟수 제한을 적용할 것.
이메일 발송 서비스의 인증 정보와 비밀키는 안전한 서버 측 환경에서 관리할 것.
외부 서비스 연동에 필요한 계정 생성, 인증, 환경변수 설정 등 사용자가 직접 해야 하는 작업이 있다면 구체적으로 안내할 것.

7-2-5. 편지 UI
기존 은하재의 따뜻하고 아기자기한 디자인과 어울리는 UI를 제작할 것.
실제 종이 편지를 펼쳐 읽는 듯한 느낌을 줄 것.
편지 읽기와 편지 쓰기 화면 모두 편지지 디자인을 활용할 것.
편지 본문이 잘 읽히도록 글자 크기와 줄 간격을 적절하게 설정할 것.
편지를 열고 닫는 과정에서 기존 카메라 조작이나 다른 상호작용과 충돌하지 않도록 할 것.
모바일과 PC 모두에서 정상적으로 표시되고 사용할 수 있도록 할 것.

7-3. 성능 및 안정성
별똥별은 기존 Three.js 환경과 렌더링 구조를 재사용할 것.
별똥별을 위해 불필요한 조명이나 무거운 파티클을 추가하지 말 것.
별똥별 애니메이션이 끝나면 관련 리소스와 이벤트를 정리할 것.
우체통은 기존 오브젝트 및 상호작용 구조를 재사용할 것.
중복 이벤트, 타이머, 애니메이션 루프가 생성되지 않도록 할 것.
모바일에서 속도나 부하, 메모리 사용에 문제가 있지 않도록 할 것.
기존 낮, 노을, 밤 모드와 불꽃놀이, 눈 모드, NPC 및 오브젝트 상호작용이 정상적으로 작동하는지 확인할 것.

7-4. 최종 확인
밤 모드에서 별똥별이 불규칙하게 등장하는지 확인할 것.
낮과 노을 모드에서는 별똥별이 등장하지 않는지 확인할 것.
우체통을 클릭하면 편지 읽기와 편지 보내기를 선택할 수 있는지 확인할 것.
편지 읽기에서 준비된 편지가 정상적으로 표시되는지 확인할 것.
편지 보내기에서 작성한 내용이 실제 운영자 이메일로 전달되는지 확인할 것.
이메일 발송 성공과 실패 상황이 정확하게 처리되는지 확인할 것.
PC와 모바일에서 UI와 상호작용을 확인할 것.
기존 기능에 오류나 성능 저하가 발생하지 않는지 확인할 것.
가장 중요한 것은 은하재의 고요하고 따뜻한 분위기를 유지하는 것임.
별똥별과 우체통 모두 과도하게 눈에 띄기보다는 공간을 천천히 둘러보다가 발견하는 작은 즐거움이 되도록 구현할 것.
